# i18n: keyed JSON catalogs, lazy-loaded languages, and a French translation

## Motivation

Nuvio's translations are currently inline pairs (`hgTr('pl', 'en')`) plus a few dictionaries (`HG_I18N`, `HG_WZ_T`, `HG_PL`, `HG_WX_SHORT`, `HG_BG_SET`). That works for two languages, but each new language means touching every call site, and every language ships inside the bundle. This PR replaces that with keyed JSON catalogs so that adding a language is adding one JSON file, and it adds French (interface and documentation) as the first language built that way.

## How it extends the existing idea

`HG_I18N` and `HG_WZ_T` already were key-to-text tables. This PR generalises them to the whole code base: one catalog per language (`src/locales/<code>.json`), nested keys named after the role of the text (`cards.smartlock.ago_minutes`, `wizard.*`, `nav.*`, `states.*`, `weather.*`, `backgrounds.*`), named variables (`{name}`) and plural suffixes (`_one/_few/_many/_other`, chosen with `Intl.PluralRules`). The API is `hgT('key', params)`, `hgTLazy('key', params)` (resolved when coerced to a string) and `hgTD` for dynamic prefixes (HA states, weather). The old helpers (`hgTr`, `hgTrO`, `hgTrLazy`, `hgI`, `HG_I18N`, `HG_WZ_T`, `HG_PL`, `HG_WX_SHORT`) are gone.

## Architecture

- **Catalogs**: `en.json` is the reference and is embedded in the bundle (always available, no request for English). Every other catalog is compiled by the build to `dist/nuvio-locale-<code>.<hash>.json` and loaded on demand. Each source catalog has `_meta` (`name`, `locale`, optional `flag`, `intro`).
- **Build compaction**: literal keys exist only in the sources. `tools/build.py` replaces each static key by an integer index (`hgT(842, p)`) and compiles catalogs into arrays (`{ "m": …, "t": [...], "d": {...} }`); plural forms are a form object stored at one index; dynamic prefixes (`states.*`, `weather.*`) stay in a small `d` table. The build fails if a literal key remains in the bundle. A compiled catalog is only valid for the core of the same build (the manifest ties them by hash).
- **Manifest**: generated by the build and embedded in the bundle (`code, name, locale, file`); language lists, pickers and browser detection derive from it, with no network request.
- **Lazy loading**: language order is unchanged (personal choice, `language:` option, wizard, browser). Browser detection tries the full code (`pt-br`), then the language (`pt`), then English. `hgT` stays synchronous and reads the in-memory catalog; fallback is chosen language, then English. A static key missing from `en.json` fails `tools/i18n_check.py` and the build, so no raw key can reach the screen (an index without English text would show as `#<index>`, visible on purpose); `hgTD` falls back to the value it is given.
- **Loader preload**: `dist/nuvio.js` guesses the language (stored choice, else browser) and starts the catalog download in parallel with the core, which reuses the pending promise. If the effective language differs, the core loads the right one afterwards.
- **First render**: the strategy waits for the catalog (3 s maximum, then it generates in English). A catalog arriving later becomes active only if it is still the chosen language: cards re-render (`hg-lang`), and a strategy page whose config was generated in another language (`_hgCode` in the config) asks Home Assistant to regenerate the dashboard (`config-refresh`, once per language), so navigation and view titles switch too, without a reload. Switching language loads the catalog, then refreshes the same way, without a page reload and without mixed display.
- **Errors**: missing or invalid catalog gives English plus a `console.warn`, never a toast.

## Non-regression guarantee

The rule was that Polish and English display must not change, other than the listed items below.

- **Migration script** `tools/i18n_migrate.py` (re-runnable to catch up with upstream commits): extracts every call and dictionary entry, proposes keys into a review table (`tools/i18n_migration_table.csv`), applies one namespace at a time, and has a built-in **equivalence proof**: for every replaced call, the rendering of `en.json[key]` and `pl.json[key]` with the variables substituted must equal the old text, otherwise the script fails.
- **Text snapshot against v2.16.0**: `tests/i18n_snapshot.py` renders `tests/cards-demo.html` and `tests/ui-gallery.html` (PL and EN, frozen clock) and collects text nodes, `aria-label`, `title`, `placeholder` and `alt` across shadow roots, per component. The baseline was built from the v2.16.0 commit and compared after each migration lot. Only the accepted differences below remain.
- **Before/after probes** (wizard, edit mode, overlays and other states the static snapshot does not reach) were scripted with Playwright against `tests/cards-demo.html`, driving real `nuvio-page` elements, before and after each lot. `tests/js/` holds unit tests (Node, no browser). `tests/local_ha.py` got a `--locale pl-PL|en-US|fr-FR` option for a run against a real local Home Assistant; that run has not been done yet (see the last item of Testing done).
- **Static checks**: `tools/i18n_check.py` (keys, variables, plural forms, `_meta`, coverage; flags untranslated literals in code; refuses markup, `on…=` handlers and, outside English, straight double quotes in catalog texts, since they are inserted as HTML; language codes are lowercase file names) and `tools/guard.py`. A failed build leaves `dist/` untouched.

## Bundle size

One-off measurement (`stat` for raw size, `gzip -9` for gzip), no threshold in the build. Reference is v2.16.0 `nuvio-core` at 1 413 609 bytes raw / 415 975 gzip.

| File | Raw | gzip |
|---|---:|---:|
| `nuvio-core` v2.16.0 | 1 413 609 | 415 975 |
| `nuvio-core` after this PR (final) | 1 372 248 (-2.9 %) | 390 674 (-6.1 %) |
| `nuvio-locale-pl` | 71 274 | 22 271 |
| `nuvio-locale-fr` | 78 625 | 22 626 |

An English user downloads 25 301 fewer gzip bytes than before; a Polish user 390 674 + 22 271 = 412 945, still 3 030 fewer; a French user 390 674 + 22 626 = 413 300, 2 675 fewer. The compiled PL catalog is larger than first estimated because it also holds the dynamic tables and plural forms. The numbers come from `docs/superpowers/notes/bundle-size.md`.

## Adding a language

Documented in `docs/configuration.md#adding-a-language`. In short: copy `src/locales/en.json` to `src/locales/<code>.json`, fill `_meta`, translate the values (keep keys, `{variables}` and plural suffixes), check with `python3 tools/i18n_check.py --lang <code>`, then build. No code change; the language shows up in Settings, the user menu and the wizard, and `language: <code>` and browser detection accept it. Missing keys fall back to English; only `en`, `pl` and `fr` are required to be complete.

## Behaviour changes and deviations

Visible changes in PL / EN (all small):

- Polish plurals now use `Intl.PluralRules`: open count 22-24, 32-34… reads "otwarte" instead of "otwartych" (sensors), and room "add tiles" 22-24… reads "kafelki". These are grammar fixes.
- Purifier presets in English with inner capitals ("SLEEP") now show the catalog label "Sleep".
- Edge cases in the room "add tiles" text now give an empty string instead of "undefined"; a backup import error is no longer re-translated mid-sheet.
- A `language:` option (or stored choice) naming a language Nuvio does not have, e.g. `de`, now falls back to browser detection instead of straight English.
- Card picker names and descriptions (`window.customCards`) are lazy getters so they follow the loaded language.
- One demo-only snapshot difference: the Polish timer card value (4:32 vs 4:27, 23 % vs 22 %) because the demo countdown now starts on the catalog-arrival re-render; no text or logic change in real Home Assistant.

Deviations from the original design:

- Compiled catalogs live flat in `dist/nuvio-locale-<code>.<hash>.json`, not in `dist/locales/`: HACS only ships top-level files of `dist/` (same reason the backgrounds are flat `nuvio-bg-*`). The manifest `file` is the bare file name, and the HACS install must contain `nuvio-locale-*.json` next to `nuvio.js`.
- Plural forms are stored as a forms object at one index rather than one index per form (functionally equivalent).
- Standalone cards (outside the strategy) render English first and re-render when the catalog arrives, rather than waiting (`hgT` is synchronous); a brief English flash on those cards only.
- `en.json` `_meta.locale` is `en-GB` (keeps `HG_LOC()` as in v2.16.0).
- For plural forms zero/one/two a translation may omit the English variables ("Une entité"); keys taking a count were turned into plural-shaped entries (`_one/_other`, with the original output kept in PL and EN).
- Module-load-time calls (`hgReg` names and descriptions) use `hgTLazy`, which is why the card picker uses getters.
- Polish-only literals (some card descriptions, a few neutral labels such as "Stop", "offline", "Alarm") got keys with `en` = `pl` = the existing literal, so display is unchanged and French can translate them. This is an English gap that already exists upstream; English-speaking contributors may want to fill it.
- Raw Home Assistant attribute values printed as is (`auto`, `sleep`, `humidifying`…) stay raw in every language, as in v2.16.0; `aria-label="dashboard"` and mock percentages in demo pages are left as is; `Assist` stays literal as a brand.
- Pre-existing bug, not touched: the English flow component sheet throws, same as at the base commit.
- Small code fixes so French reads correctly, with PL and EN output unchanged (snapshot): NBSP before "!" in the hero card, unpluralised counts in map, players and sensors cards, hard-coded "d" suffix in the room card, `': '` and `%` formatting built in code.
- `dist/` is regenerated in the last commit of each migration lot instead of every commit, to avoid many 1.4 MB blobs in history (intermediate commits can carry a stale `dist/`, relevant only for bisecting).

- `python3 tools/i18n_check.py`: en, fr and pl complete (2 736 keys in `en.json`).
- `python3 tools/guard.py` passes.
- Text snapshots PL and EN compared to v2.16.0 (accepted differences above only); standalone-card check (catalog delayed 1 s, re-render without reload).
